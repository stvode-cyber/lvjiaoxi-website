# UX 测试手册 · UX Test Playbook

> 配套 Agent：`.trae/agents/core/ux-experience-tester.md`
> 触发语："跑 UX 测试" / "测一下体验" / "找一键化机会"

## 触发条件

| 触发语 | 行为 |
|--------|------|
| "跑 UX 测试" / "测一下体验" | 完整黑盒冒烟 + 一键化扫描 + 输出优化报告 |
| "测一下 [页面名]" | 只测指定页面的用户旅程 |
| "做兼容性测试" | 多设备/多浏览器矩阵测试 |
| "找一键化机会" | 扫描全站，列出所有可以简化为一键的操作 |
| "跑异常测试" | 断网、慢网、重复点击、乱输数据 |
| "UX 走一遍" | 快速黑盒冒烟（5 分钟版） |

## 一、常见 UX 反模式清单

测试时逐条检查，发现任何一条就记下来：

### 1. 导航反模式

| 反模式 | 用户感受 | 绿角犀检查点 |
|--------|---------|-------------|
| **深层导航隐藏主要内容** | "我要的东西在哪？" | 下载按钮是不是被挤到次要位置？ |
| **导航栏在滚动时消失** | "想切换页面又得滚回顶部" | 首页滚到底后导航还在吗？ |
| **面包屑没有"首页"** | "想回去只能点浏览器后退" | 产品详情页面包屑有没有首页链接？ |
| **分类全是文字没有图标** | "分类太多看不过来" | 产品分类有没有图标？ |

### 2. 表单反模式

| 反模式 | 用户感受 | 绿角犀检查点 |
|--------|---------|-------------|
| **提交后需要刷新页面** | "我等一下看有没有成功" | contact.html 提交后有没有直接显示确认？ |
| **错误提示只说"出错了"** | "到底哪错了？" | 留言输错后是不是明确说"名字不能为空"？ |
| **必填标记不明显** | "我漏填了什么？" | 必填项有没有红色星号？ |
| **表单太长不分步** | "不想填了" | 后台管理员新增表单是不是一次全塞？ |
| **没有输入格式提示** | "我该怎么填？" | 邮箱框有没有 placeholder 提示格式？ |

### 3. 加载反模式

| 反模式 | 用户感受 | 绿角犀检查点 |
|--------|---------|-------------|
| **白屏等待** | "是不是挂了？" | 首屏有没有骨架屏？ |
| **loading 动画比内容还慢** | "等不及了关掉" | 骨架屏有没有超过 2 秒还在？ |
| **断网不提示** | "为什么点不动？" | 离线时有没有显示 offline.html？ |
| **图片没 alt 或占位** | "加载失败全是破图" | 产品图有没有占位符？ |

### 4. 下载反模式

| 反模式 | 用户感受 | 绿角犀检查点 |
|--------|---------|-------------|
| **不识别用户系统** | "我该下哪个？" | download.html 有没有自动识别 OS 并默认选中？ |
| **下载按钮太小** | "找不到下载" | 手机上下载按钮宽度够吗？（≥180px） |
| **点了没反应** | "到底下没下？" | 下载有没有明确的"开始下载"反馈？ |
| **需要登录才能下载** | "还要注册？算了" | 下载是匿名的吗？ |

### 5. 移动端反模式

| 反模式 | 用户感受 | 绿角犀检查点 |
|--------|---------|-------------|
| **点击目标 < 44×44px** | "总是点错" | 所有可点击元素够大吗？ |
| **表格横向溢出** | "左右滑好烦" | 后台管理员列表在手机上能看吗？ |
| **hover 才有交互** | "手机上没有 hover" | 导航下拉菜单是 hover 还是 click？ |
| **竖屏转横屏布局崩坏** | "转个方向就乱了" | 横屏下导航是不是重叠？ |

## 二、一键化机会识别规则

### 核心原则

> **用户现在需要 N 步完成的事，能不能变成 1 步？**

### 识别框架

```
对每个用户操作，自问 5 个问题：
1. 这个操作能不能省掉？（YAGNI）
2. 能不能自动识别用户意图，跳过选择？
3. 能不能把多步合并成一步？
4. 能不能在后台悄悄做，不让用户等？
5. 能不能在正确的时机给正确的按钮？
```

### 具体识别信号

| 信号 | 一键化建议 |
|------|-----------|
| 用户需要先选再下载 → 自动识别 OS | 浏览器 `navigator.userAgent` 判断 → 默认选中对应下载按钮 |
| 用户需要填完表单才知道格式错 → 实时校验 | 邮箱框输入时就校验格式，不用等提交 |
| 用户需要滚到底才看到评分 → 固定显示 | 评分卡片 sticky 在侧边栏，滚动时始终可见 |
| 用户需要 2 次点击才完成关键操作 → 合并 | 下载按钮 + 版本号合并成一个大按钮 |
| 用户需要手动刷新看结果 → 自动更新 | 反馈提交后，列表 `location.reload()` 改成 `fetch + DOM 更新` |
| 用户需要记 URL 才能分享 → 一键复制 | 每页加"分享"按钮，`navigator.clipboard.writeText()` |
| 用户需要对比多个产品才能选 → 问卷推荐 | "帮我选"3 个问题 → 推荐最匹配的产品 |
| 用户需要进后台才能改内容 → 行内编辑 | 管理员列表双击行 → 直接编辑 → 失焦自动存 |

### 一键化机会输出格式

```markdown
## 🎯 一键化机会 Top N

| # | 页面 | 当前步骤 | 建议步骤 | 节省 | 难度 | 验收标准 |
|---|------|---------|---------|------|------|---------|
| 1 | xxx | A→B→C | A→C | 1 步 | 🟢 | 用户不需要中间选择 |
| 2 | xxx | A→B→C→D | A→D | 2 步 | 🟡 | 页面不刷新即看到结果 |
```

### 难度评估标准

| 等级 | 工作量 | 例子 |
|------|--------|------|
| 🟢 低 | 改 CSS 或加 1 段 JS | 下载按钮加宽、导航栏吸顶 |
| 🟡 中 | 加 HTML + CSS + JS，不碰后端 | 固定评分侧边栏、行内编辑 |
| 🔴 高 | 需要改 API 或加新服务 | 帮我选问卷推荐、短链生成 |

## 三、黑盒测试流程模板

### 流程 A：5 分钟快速冒烟（一句话触发版）

```
1. 打开首页 index.html
   → 骨架屏消失了吗？（≤ 2s）
   → 首屏下载按钮看得见吗？
   → 导航栏正常吗？
2. 点产品卡片进 product.html
   → 产品详情正常显示？
   → 有下载按钮吗？
3. 点下载按钮
   → 有下载行为或跳转吗？
4. 断网刷新
   → 显示 offline.html 吗？
5. 手机尺寸（375px）
   → 导航折叠正常吗？
   → 下载按钮够大吗？
6. 深色模式
   → 对比度够吗？（WCAG AA）
```

### 流程 B：完整黑盒冒烟（15 分钟版）

```
1. 首次访问旅程
   ├─ 首页加载（骨架屏、动效、下载按钮）
   ├─ 产品详情（图片、评分、反馈入口）
   ├─ 下载（自动识别 OS、版本号）
   └─ 返回首页（导航栏吸顶）
2. 联系旅程
   ├─ 进 contact.html
   ├─ 填表单（正常 / 空 / 超长 / emoji / SQL）
   ├─ 提交 → 确认反馈
   └─ 列表自动刷新？
3. 反馈旅程
   ├─ 进产品页
   ├─ 写反馈 + 评分
   ├─ 提交 → 评分实时更新？
   └─ 列表自动刷新？
4. 后台旅程
   ├─ 登录（正常 / 错 6 次锁 5 分钟）
   ├─ 产品管理（列表 → 新增 → 编辑 → 删除）
   ├─ 分类管理（CRUD）
   ├─ 统计看板（数字对吗）
   └─ 修改口令 → 旧 token 失效？
```

### 流程 C：异常操作矩阵

| 场景 | 操作 | 期望 |
|------|------|------|
| 断网 | DevTools → Offline → 刷新 | offline.html，重试按钮 |
| 慢网 | DevTools → Slow 3G | 骨架屏，不白屏 |
| 重复点击 | 下载按钮连点 10 次 | 只触发 1 次 |
| 长文本 | 留言框贴 5000 字 | 截断或友好提示 |
| SQL 注入 | 留言输 `' OR 1=1 --` | 正确转义，不崩 |
| XSS | 留言输 `<script>alert(1)</script>` | 转义，不执行 |
| 超长密码 | 注册密码输 1MB | 明确提示限制 |
| 狂点登录 | 登录按钮 1 秒点 20 次 | 防抖 + 锁定 |
| 改 URL | 直接访问 `/admin` 未登录 | 跳转登录页 |
| 改 token | JWT 改几个字符 | 401，不是 500 |

### 流程 D：兼容性矩阵

| 维度 | 参数 | 检查项 |
|------|------|--------|
| 桌面浏览器 | Chrome / Edge / Firefox / Safari | 下载按钮、动效、深色模式 |
| 移动浏览器 | iOS Safari / Android Chrome | 导航折叠、点击目标 ≥44px、横竖屏 |
| 尺寸 | 1920×1080 / 1366×768 / 768×1024 / 375×812 | 内容不溢出、布局不崩坏 |
| 网络 | 正常 / Slow 3G / Offline | 骨架屏、离线提示 |
| 模式 | 浅色 / 深色 | 对比度 WCAG AA（4.5:1） |

## 四、Nielsen 可用性启发式原则（10 条）

> 测试时逐条对照，每条至少找 1 个检查点。

| # | 启发式 | 绿角犀检查点 | 通过标准 |
|---|--------|-------------|---------|
| 1 | **系统状态可见** | 下载中、提交中、保存中有没有 loading？ | 每个异步操作 ≤ 300ms 给出反馈 |
| 2 | **系统与现实匹配** | 按钮文案是不是用户熟悉的词？ | "下载"不是"获取安装包" |
| 3 | **用户控制与自由** | 填到一半想取消，有没有明确按钮？ | 每个可丢弃的操作都有"取消" |
| 4 | **一致性与标准** | 全站"提交"按钮都在右下吗？ | 位置、颜色、样式完全一致 |
| 5 | **错误预防** | 密码输错有没有提示剩余次数？ | 告诉用户"还能试 X 次" |
| 6 | **识别而非回忆** | 分类用图标还是文字？ | 图标 + 文字，不强迫回忆 |
| 7 | **灵活与高效** | 有没有快捷键或 Power 用户模式？ | 后台支持 `Ctrl+S` 保存 |
| 8 | **美学与极简** | 首页有没有多余信息？ | 首屏只有品牌 + 核心功能 + 下载 |
| 9 | **帮助用户识别/恢复错误** | 断网了告诉用户怎么恢复？ | offline.html 有"检查网络"按钮 |
| 10 | **帮助与文档** | 新手引导在哪？ | 首次访问有引导提示 |

### WCAG 2.1 AA 快速检查

| 项目 | 标准 | 绿角犀检查 |
|------|------|-----------|
| 颜色对比度 | 正文 ≥ 4.5:1，大字 ≥ 3:1 | 深色模式下按钮和背景对比度 |
| 键盘可访问 | 所有功能能用 Tab 键访问 | admin.html 能不能纯键盘操作 |
| 图片 alt | 所有 img 有描述性 alt | 产品图、logo 的 alt |
| 表单标签 | 每个 input 有 label 或 aria-label | 留言框有没有 label |
| 焦点指示 | 键盘焦点有明显视觉指示 | Tab 时有没有轮廓线 |

## 五、禁止事项

- **不要只测理想路径** — 必须测异常、边界、搞破坏
- **不要假设用户会看教程** — 默认用户不看任何帮助文档
- **不要给纯技术建议** — 建议必须说清楚用户感知的变化
- **不要遗漏验收标准** — 每条建议必须有"改完怎么验证"
- **不要把反模式写成假设** — 必须实际看到用户会踩的坑
- **不要只看 PC 不看手机** — 手机是主要访问渠道
- **不要忽略深色模式** — 绿角犀主打安全浏览器，深色是核心卖点

## 六、踩坑速查

> 真实踩过的 UX 问题，每次测完后补。

| 日期 | 问题 | 根因 | 修复 | 下次检查 |
|------|------|------|------|---------|
| 2026-09 | 下载按钮在手机上看不见 | 120px 太窄，被导航栏挤 | 加宽到 180px | 所有可点击目标 ≥ 44×44px |
| 2026-09 | 提交后需要手动刷新 | 用了传统 form submit | 改成 fetch + DOM 更新 | 所有表单提交后自动更新列表 |
| 2026-09 | 评分藏在页面底部 | 没有固定显示 | 加 sticky 侧边栏 | 关键信息在滚动时始终可见 |
| 2026-09 | 骨架屏白屏 2 秒 | 图片太大没占位 | 加 CSS 占位 + 懒加载 | 首屏所有图片有占位 |
