# AI 辅助功能设计

## 触发条件
产品讨论、功能规划、或用户说"能加 AI 吗"时使用。

## 核心判断

绿角犀定位**极简安全浏览器官网**，不是 AI 驱动的 SaaS。AI 辅助**只做功能增强，不做核心功能**。

## 可落地的 AI 功能

### P1 — 低成本高价值

| 功能 | 做法 | 竞品参考 | 绿角犀版本 |
|------|------|---------|-----------|
| **AI 安全助手文案** | 产品页加一段"AI 驱动的威胁识别"描述 | 360 AI 助手 | 静态文案 + AI 图标，不接 API |
| **AI 划词翻译介绍** | 下载页加"内置 AI 翻译"特性 | 360 AI 划词 | 同上，产品特性展示 |
| **智能截图 OCR** | 产品页加"截图即识别"特性 | 360/Edge | 同上 |

### P2 — 中等成本

| 功能 | 做法 | 备注 |
|------|------|------|
| **安全 AI 聊天入口** | 官网加"AI 安全顾问"按钮，跳转到外部 AI 服务 | 用免费 AI（如 豆包/文心）做安全问答 |
| **智能产品推荐** | 后台按用户反馈/评分自动排序产品 | 简单加权即可，不用 ML |
| **AI 自动生成 changelog** | 后台新增产品时自动生成 changelog 草稿 | 规则模板 + 人工审核 |

### P3 — 高成本（暂缓）

| 功能 | 原因 |
|------|------|
| AI 驱动的安全体检 | 需要后端接 LLM API，成本高 |
| 智能客服聊天机器人 | 需要持续训练 + API 费用 |
| AI 内容生成 | 官网内容少，投入产出比低 |

## 官网 AI 功能的边界

```
✅ 产品特性描述里提 AI（"AI 驱动的威胁识别"）
✅ AI 图标 + 文案增强信任感
❌ 官网直接接入 LLM API（增加延迟 + 成本 + 隐私）
❌ AI 作为核心功能（偏离极简定位）
❌ 收集用户数据做 AI 训练（隐私红线）
```

## 实现建议（P1 级）

### 方式 A：纯展示（当前推荐）

```html
<!-- index.html 首屏特性 -->
<div class="feature-card" data-animate>
  <div class="feature-icon">🤖</div>
  <h3>AI 智能防护</h3>
  <p>基于机器学习的威胁识别，实时拦截钓鱼、挂马、仿冒网站</p>
</div>
```

### 方式 B：AI 图标 + 链接（可选）

```html
<a href="/ai-safety" class="ai-entry">
  <span class="ai-badge">AI</span>
  <span>安全顾问</span>
</a>
```

### 方式 C：后端 AI 辅助（P2 时考虑）

```js
// server/routes.js 加
router.get('/api/ai/security-tips', (req, res) => {
  // 从预写的安全提示池随机返回
  const tips = [
    '钓鱼网站通常伪装成知名品牌，注意检查网址拼写',
    '下载软件只从官方渠道获取',
    '定期更新浏览器以获得最新安全补丁',
  ];
  res.json({ tip: tips[Math.floor(Math.random() * tips.length)] });
});
```

## 安全红线

- **不要在官网收集用户数据用于 AI 训练**
- **不要用 AI 生成未经审核的内容**（安全相关错误信息误导用户）
- **不要承诺 AI 能 100% 拦截**（安全无绝对）
- **所有 AI 相关描述加"辅助"、"增强"限定**（不说"保证"、"彻底"）

## 禁止事项

- 不要在官网前端直接调 LLM API（泄露 API Key）
- 不要引入 AI SDK 增加前端体积（保持极简）
- 不要把绿角犀定位改成"AI 浏览器"（定位是安全浏览器，AI 是特性）
- 不要承诺 AI 功能"完全免费"（API 有成本）
