⚠️ 本次踩坑（重要，可复用）：在 Express `router.get(...)` 之后插入新路由时，原路由结尾的 `});`（关闭 router.get 调用）往往不在被替换的 old_string 内，会被"遗留"到新路由之后，导致新路由多出 `}););` 且原路由漏闭合 → 启动报 `SyntaxError: missing ) after argument list`。修复办法：插入新路由时，确保原路由结尾用 `});` 正确闭合（箭头函数 `}` + router.get 调用 `)`），并删除尾部多余 `);`。编辑多路由文件后务必 `node --check`。

## 第二十轮：代码审查 + 安全加固（本次审查发现并修复 3 处问题）
- 审查对象：config.js / routes.js（全量）/ server.js / auth.js / db.js。整体良好（SQL 全参数化、限流、蜜罐、CSP 到位）。发现 3 处真实问题并修复：
- ① 目录穿越漏洞（高危）：HTML 托管中间件用 `path.join(root, decodeURIComponent(req.path))` 且未校验落点；`req.path` 不被 Express 归一化，原始 `GET /../x.html` 可逃出 web 根读取任意 .html。修复：先 `path.normalize` 再校验 `file === root || file.startsWith(root + sep)`，否则 `next()`（落 404）。
- ② 反向代理下限流/防暴破失效：限流与登录锁均按 `req.ip`，未设 trust proxy 时部署在 nginx/Caddy 后 `req.ip` 全为 127.0.0.1，所有客户端被归并、保护失效。修复：`server.js` 在 `express()` 后 `app.set('trust proxy', 1)`（信任前置单代理）。
- ③ 产品更新类型未校验：`PUT /admin/products/:id` 接受任意 `type`。修复：当 `b.type` 存在且非 app/game 时返回 400。
- 重启服务（旧进程释放 :3000，新进程 mR4bHe；S3d3dK 因 cd 路径误用反斜杠导致未启动、属正常重启信号）。
- 验证：① 在 web 根上一级建探针 probe-traversal.html（含 SECRET_LEAK），`GET /../probe-traversal.html` 经 `--path-as-is` 返回 404 友好页、**未泄露**内容（确认拦截）；`/%2e%2e/%2e%2e/etc/passwd.html`=404；`./index.html` 仍=200；`/` 与 `/contact.html`=200。② contact 连发 6 次 = 200,200,200,200,200,429（trust proxy 未破坏本地限流）。③ 登录200；`PUT type=malware`=400、`PUT name only`=200。server.js/routes.js node --check 通过。
